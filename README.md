# H题车载平衡滚球运动控制系统

本工程用于《车载平衡滚球运动控制系统（H题）》，包含 MaixCAM 单球视觉定位、
图传、UART 通信、接收端录像以及 MCU 控制参考代码。

## 当前状态

- MaixCAM C++ 应用已完成交叉编译。
- 安装包：`dist/h_ball_balance_v1.0.3.zip`。
- YOLO `.mud` 与 `.cvimodel` 已包含在安装包的 `models/` 目录中。
- 当前 YOLO11s 模型使用真实 H 题装置视频训练；YOLO-World-L 在固定轨道 ROI 内为
  原视频全部 `1286/1286` 帧各生成唯一钢球框，并加入缩放、旋转和曝光增强。
  连续时间段留出的 257 帧验证集最佳结果为 `P=0.983`、`R=0.961`、
  `mAP50=0.983`、`mAP50-95=0.888`。这些指标衡量模型与 YOLO-World
  伪标签的一致性，并非人工标注测试集精度。模型已转换为 MaixCAM CV181x INT8 格式。
- UART 数据帧解析单元测试已通过。
- MCU 目录目前提供平台无关的控制核心，不包含特定芯片的时钟、GPIO、PWM、
  UART DMA、红外 ADC 和屏幕 HAL。
- 视觉坐标、控制增益和停车参数必须使用最终车体实测，代码中的数值只是安全初值。

## 系统分工

- **MaixCAM Pro**：摄像头检测单颗钢球、将像素位置换算成摆杆坐标、估计速度、
  通过 UART 输出测量值、显示和 RTSP 图传。
- **车载 MCU（建议 STM32G4/F4/H7）**：读取红外光电循迹阵列、启动按键，驱动
  左右电机和摆杆舵机/电机，运行 100~500Hz 控制环，计时并在不大于 2 英寸的
  屏幕显示时间。
- **接收端电脑/PAD**：实时显示图传并完整录像、回放。比赛封存的是接收设备，
  因此录像不能只依赖临时播放器缓存。

小车循迹严格只使用红外光电模块。摄像头只检测摆杆内的钢球，符合题目限制。

## MaixCAM 功能

- YOLO11 单球检测，并先用固定中间轨道 ROI（320×240 画面中的
  `x=8..312, y=96..142`）排除轨道外目标，再沿标定后的摆杆轴线筛选。
- 默认置信度阈值为 `0.40`；现场可修改 `balance_calibration.cfg` 后重启应用。
- 两点投影标定，将斜拍画面中的二维中心映射为一维厘米坐标。
- alpha-beta 滤波输出位置和速度；短时漏检可预测 250ms，超过后置无效标志。
- `640x480@20fps`、约 `2Mbps` 的 H.264 RTSP 图传，叠加位置、目标值和检测框。
- 触屏选择测试模式与任意目标位置。
- 以 `115200 8N1`、无流控向 MCU 发送位置误差与速度测量包。

RTSP 地址：

```text
rtsp://10.243.41.1:8554/live
```

## 标定

摄像头必须刚性固定，画面覆盖整个 25cm 摆杆。建议用刻度上的 `-10cm` 和
`+10cm` 两点标定，避免在机械端点放球困难：

1. 将球放到 `-10cm` 刻线，等框稳定后按 `CAL-L`。
2. 将球放到 `+10cm` 刻线，等框稳定后按 `CAL-R`。
3. 配置自动写入 `balance_calibration.cfg`。
4. 分别把球放在 `0cm`、`±5cm`，检查屏幕误差；必须小于 `0.3cm` 再调控制器。

按钮含义：

- `MODE`：`MON -> SWEEP -> AB-O -> LAP-O -> LAP-X`。
- `T-/T+`：任意位置每次调整 `0.5cm`，范围 `-10~+10cm`，并进入 `LAP-X`。
- `EXIT`：退出应用。

正式启动必须使用 MCU 上的物理按键；触屏只选择模式和标定，不替代题目要求的
启动按键。

## UART 协议

帧固定为20字节：

```text
AA BB | len=10 | delta_x:double-le | delta_y:double-le | checksum:u8
```

字段定义：

- `delta_x = target_cm - position_cm`，即钢球位置误差，单位厘米。
- `delta_y = velocity_cm_s`，即钢球速度，单位厘米/秒。
- 两个数都是 IEEE-754 64位 `double`，按小端序发送。
- 无有效测量时两个字段均发送 `NaN`。
- `checksum` 只对16个 `double` 数据字节累加并取低8位，不包含帧头和长度。

串口为 `115200 8N1`、无流控。MaixCAM 使用 A16(TX)/A17(RX)，连接 STM32
PA9(TX)/PA10(RX) 时必须 TX/RX 交叉并共地。MCU 解析参考见
`mcu_reference/vision_protocol.c`。新协议不传输模式和目标值，MCU 运行模式必须在
本地设置。超过250ms没有有效测量时，参考控制器会停止车辆并把摆杆回中。

## 五种模式

| 模式 | 对应任务 | 钢球目标 | 小车动作 |
|---|---|---:|---|
| MON | 调试/标定 | 只监测 | 停止 |
| SWEEP | 要求3 | `0 -> +5 -> -5cm` | 静止 |
| AB-O | 要求4 | `0cm` | A 到 B |
| LAP-O | 要求5 | `0cm` | 顺时针一圈 |
| LAP-X | 要求6 | 触屏指定 | 顺时针一圈 |

要求2只需 MCU 循迹和停车，可用 `LAP-O` 但忽略球控评分，或在 MCU 菜单中单独
设置纯循迹模式。

## 编译与运行

```bash
cd h_ball_balance
MAIXCDK_PATH=/path/to/MaixCDK maixcdk build -p maixcam
./h_ball_balance ./models/stainless_ball.mud /dev/ttyS0 ./balance_calibration.cfg
```

直接从应用启动器运行时会自动使用包内模型。如果尚未接 MCU，可把串口参数改为
`none`，视觉与图传仍能独立运行。

## 接收、录像和回放

```bash
cd receiver
./view_low_latency.sh
./record.sh                    # q 停止并正确封装录像
./replay.sh records/H_test_20260729_123456.mkv
```

正式测试前应确认接收端磁盘空间、系统时间和录像回放均正常。RTSP 中断后不要直接
拔电，应先在 ffmpeg 中按 `q`，确保录像文件完成封装。

## 控制器整定顺序

1. 车轮悬空，仅验证方向、急停和启动线识别。
2. 小车静止，先只调摆杆速度阻尼 `ball_kd`，再加位置比例 `ball_kp`，最后加很小
   的积分消除静差；摆杆角度先限制在 `±5°`。
3. 完成静态 `0/+5/-5cm` 后再把角度上限逐步放到 `±10°`。
4. 低速循迹时调球控，再提高车辆速度。弯道的横向加速度是主要扰动，不能一开始
   就按 20s 圈速测试。
5. 最后调红外循迹 PID、A 点防重复计数和提前刹车距离。

`mcu_reference/control_core.c` 是与芯片无关的控制核心示例，PWM、红外采样、屏幕、
按键和 UART DMA 需要接入所选 MCU 的 HAL。其中增益只是安全初值，必须根据实际
摆杆执行器、舵机方向、重心和相机帧率重新整定。
